# chaff で文章を確かめる

chaff は、読みにくい文章（長すぎる文、水増し、文末のゆれ、見出しの抜けなど）を機械で見つける。
同じ文章なら何度かけても同じ結果になる。文章は書き換えない。読んで直すのは、あなた（AI）の仕事。

出どころ：有本勇さんの chaff 同梱 skill を、業務ハーネス向けに日本語で移したもの。
原本： https://github.com/isamu/lab/tree/main/text/packages/chaff/skills/chaff/SKILL.md
原本は英語で、法令・論文・小説なども扱う。ここでは報告と業務文書に絞っている。

## まず、文書の種類（ジャンル）を決める

ジャンルは「文書の種類ごとの検査の設定」。種類を間違えると、的外れな指摘が出る。
- 報告・社内文書：`business/report`
- メール：`business/email`
- 議事録：`business/meeting-notes`
- マニュアル・手順書：`docs/manual`
- 迷ったら `npx chaffjs genres` で一覧を見る

AI の報告は `報告/chaff.yaml` に `genre: business/report` が書いてある。
実行するフォルダから設定を読むので、必ず `cd 報告` してから実行する。
出力の1行目に「ジャンルは chaff.yaml から」と出ているか確かめる（「既定から」なら設定が読めていない）。

## 実行する

```sh
cd 報告
npx -y chaffjs 報告_日付.md            # 読みやすい形で出す
npx -y chaffjs 報告_日付.md --compact  # 1件2行で出す
```

- error（エラー）が1件でもあると、終了コードが 1 になる。何も検査できなかったときも 1。0 なら、検査できている。
- 指摘の下に「動いていない rule」の一覧が出る。「指摘なし」と言う前に、これを読む。
- 複数ファイルを一度にかけると、指摘のあるファイルしか出ない。1ファイルを「問題なし」と言うときは、そのファイルだけでかけ直す。

## 指摘ごとに、3つから選ぶ

| 選ぶもの | いつ | どうする |
|---|---|---|
| 文章を直す | 指摘が正しい | 意味・事実・数字は変えず、言い方だけ直す |
| その箇所だけ黙らせる | 一般には正しいが、ここでは違う（引用、繰り返す必要のある用語） | 直前に `<!-- stet: ルール名 — 理由 -->` を書く。理由は必ず書く |
| ルールを変える | このチームでは合わない | `npx -y chaffjs relax ルール名 --why "理由"`。理由と日付が chaff.yaml に残る |

`npx -y chaffjs explain ルール名` で、そのルールの目的と今の強さが見られる。ルールを緩める前に読む。

## 報告のときの決まり

- 見出しが足りない（required-sections、error）は、報告の型を守っていないということ。必ず直してから渡す。
- 2回直しても直らないときは、`03_止まる条件.md` の「同じ失敗を2回繰り返した」に当たる。止まって、持ち主に報告する。
- 注意（warning）と参考（info）が残るときは、報告の「残っていること」に、何が残っているかと理由を書く。
- 検査を通すために、報告の中身（事実・数字）を変えない。

## 設定を直すとき（chaff.yaml）

「文は80字まで」「です・ます調にそろえる」のような社内の決まりを渡されたときは、ルール名や数字を推測しない。

1. `npx -y chaffjs rules --json` を読む。各ルールに、何を見つけるか（summary）、段階（levels）、例（example）が入っている。
2. 決まりを1つずつに分け、合うルールを選ぶ。段階にない数字は、数字そのものを書く（`max-sentence-length: 80`）。
3. 表記は `prefer`、社内用語は `jargon`、必須の見出しは `required_sections` に書く。
4. ルールが扱えない決まりは、扱えないとはっきり伝える。
5. 書いたら、決まりを破った短い見本を作り、ちゃんと指摘されるか確かめる。

## 「AIっぽさをなくして」と頼まれたとき

chaff は「AIが書いたか」を判定しない。AIの文章に多い型（決まり文句、「Xではなく、Yです」の対比、太字の多用、まとめが本文の繰り返し）を指す。

1. `npx -y chaffjs fix-plan ファイル名` を実行する。直す方向、残すもの、避けること、指摘の箇所が出る。
2. 計画が勧める方式で書き直す。「全面的に」「一から」と頼まれたら、全面書き直し。
3. 事実・数字・条件・名前は変えない。足りない具体例は、作らずに本人に聞く。
4. 直したら `npx -y chaffjs compare 元 新` で、事実が落ちていないか、増えていないかを確かめる。
5. 直すのは2回まで。

## やってはいけないこと

- ルールを通すために、文書の意味を変えない。意味を変えないと直せない指摘は、直さずに理由を書いて残す。
- 検査を通すためだけに、ルールを off にしない。緩めるなら、チームが納得できる理由をつける。
- 「動いていない rule」の一覧を読まずに、「指摘なし」と言わない。
- chaff の指摘が間違っているときは、`npx -y chaffjs feedback ファイル --rule ルール名` で報告文の下書きを作れる。送るのは持ち主が決める（文書に私的な情報が入っていることがある）。
