# 業務ハーネス（gyomu-harness）

業務を一番よく知っている人が、AI と一緒に業務ツールを作るための「枠」です。
エンジニアでなくても、この枠の中で作れば大きく外れないものができる、を目指しています。

## なぜ作ったか

現場の仕事を一番知っているのは、その仕事をしている人です。
けれど、AI に作らせると「それらしいもの」はできても、どこが危ないかを本人が判断できません。

そこで、判断の一部を枠に任せます。
- AI に何を渡すか
- どこで人が確かめるか
- 何をしてはいけないか、どこで止まるか

これを先に決めておくのがハーネスです。

## 中身

| ファイル | 役割 |
|---|---|
| `harness/00_業務を言葉にする.md` | 作る前に、業務を言葉にするシート（ここが一番大事） |
| `harness/CLAUDE.md` | AI に最初に読ませるルールのひな形 |
| `harness/01_作業の切り方.md` | 1回の作業を小さく切る型 |
| `harness/02_役割.md` | 作る AI と確かめる AI と人を分ける |
| `harness/03_止まる条件.md` | AI が自分で止まって人に聞く条件 |
| `harness/04_報告の型.md` | AI からの報告を毎回同じ形にする |
| `harness/05_機械で確かめる.md` | 報告の形が崩れていないかを、文章の検査ツール chaff で機械が確かめる |
| `harness/報告/` | 報告の置き場。`chaff.yaml`（見出しの決まり）と見本 `例.md` |
| `demo/` | 研修の申込・出欠・アンケート集計ツールを、このハーネスで作った例 |

## 使い方（最短）

1. `harness/00_業務を言葉にする.md` を埋める（AI と対話しながらでよい）
2. 作りたいツールのフォルダに `harness/CLAUDE.md` をコピーし、空欄を埋める
3. Claude Code や Codex に「CLAUDE.md を読んでから、作業を1つだけ進めて」と頼む
4. AI は報告を `報告/` に書き、chaff で形を確かめてから渡す（`harness/05_機械で確かめる.md`）
5. 報告を読み、確かめて、承認する。これを繰り返す

## 私はこう使っています

研修講師・生成AIコンサルタントとして、自分の業務ツールと受託開発の両方で、毎日この枠を使っています。
作る人（AI）と確かめる人（別の AI と私）を分けることで、エンジニアでない人が作っても外れにくくなりました。
